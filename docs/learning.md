## 风云周报口径复盘 2026年9月15日

### 免考核店铺必须完整展示

三次及以上免考核店铺表必须同时展示盈利、亏损及缺数据待补的店铺，不能只筛选利润为负的记录；缺数据不得按零利润填充。

### 商务归属须以确认信息为准

待补登记姓名不等于已确认商务归属。报告按负责人确认结果更正时，须联动个人金额、环比、店数和最大贡献店，并验证团队金额守恒；报告更正不代表生产登记已更正。

### 渠道投入与产出使用同一范围

渠道全量红包和其中免考核红包、发车、窗口产出必须按同一商品、渠道和时间范围拆分。用户举例金额不得直接当成核实值；实际值须从同一范围的排单明细核对，并记录查询时间。

## 红包对账与协作规则 2026年10月12日

### 三步流程和财务确认口径必须一致

保留主管按渠道汇总提交、财务通过或打回、主管拿确认金额去钉钉审批付款的三步流程。PAID 表示财务核对确认并在系统记为已确认，不能据此宣称公司已经转账或渠道已经到账。廖宇杰负责汇总和提交，游小玲负责财务审核；实际转账仍须在系统外执行并核对凭证。

### 提交和审核必须核对所见金额版本

提交及审核必须携带页面所见的明细版本。后端在真实事务内锁定申请及排单，重算范围、数量和金额；页面版本与当前账目不一致时拒绝写入并要求刷新。不能只用前置检查或模拟事务证明安全，关联失败须整笔回滚，同一申请的并发审核只能成功一次。

### 财务确认后的金额和归属必须保护

财务确认后禁止改金额、渠道身份、红包模式、实际发车归属月份及删除；同月具体时间、备注和凭证允许修改并留痕。待审明细仍允许调整，但旧页面不得覆盖并发提交或审核后的账目。更新和删除必须在数据库写入条件中核对已确认标志及付款申请关联，旧已付入口不得改写挂有申请的明细。

### 凭证修改只能窄写并保留现有截图

修改付款凭证须锁定申请，随后只写截图及对应更新时间，不能用旧对象覆盖审批状态、金额或撤销结果。审核时没有新截图，无论字段省略还是提交空数组，都保留锁定后读取到的现有凭证；主动清空凭证只能通过专用凭证修改入口。回归测试须覆盖截图先锁和审核或撤销先锁两种顺序。

### 付款申请历史必须独立显示

主管页必须独立展示当月申请历史、状态及打回原因。历史显示不能依赖当前待提交渠道；打回后重新提交、当月全部已确认或已撤销时，仍应能追溯原申请和原因，不能因待提交明细为空就隐藏记录。

### 月份加载失败时必须禁止写入

切换月份前须撤销旧选择并标记当前数据未就绪；加载失败时显示错误并禁止提交、审核等写入。不能把上月残留表格当成本月数据，也不能把读取失败显示成零金额或空账目；只有当前月份数据成功返回且确认版本有效后才能恢复操作。

### 本地模拟真实数据库和线上证据必须分开

交付须分别说明本地模拟、真实 SQL 与事务并发、真实 Controller 接口自测、线上版本及人员试用的证据。接口验收同时核对 HTTP 状态和业务返回码；本地通过不能代表已部署、已到账或员工已验收。真实数据库回归默认关闭，仅显式指定受严格校验的独立本机测试库时运行，禁止借用生产库做写入测试。

### 渠道真实欠款必须先确认结清基准

核对微信真实欠款前，必须先逐渠道确认已结清截止日及截至该日仍遗留的欠款，再核对之后的发车、应付及实际支付。月结、现结、预存仅表示结算方式，不能把标签、系统最早发车日期或历史会话提出的日期建议当作已结清事实。实付台账没有渠道字段时，不得按全体推广转账总额猜测分摊；须取得能对应到渠道的凭证，缺少结清基准或归属证据时明确标为待核实。
